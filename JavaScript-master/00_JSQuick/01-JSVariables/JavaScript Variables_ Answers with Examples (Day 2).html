JavaScript Variables: Answers with Examples (Day 2)

Question 1: var vs let vs const

var let const
Scope Function Block { } Block { }
Re-declare in same scope Allowed Error Error
Re-assign Allowed Allowed Error
Hoisting Hoisted, value is undefined Hoisted, but in the temporal dead zone Same as let
Must initialise at declaration No No Yes 
var a = 10;
var a = 20;          // OK, re-declaration allowed
console.log(a);      // 20

let b = 10;
// let b = 20;       // SyntaxError: 'b' has already been declared
b = 20;              // OK, re-assignment
console.log(b);      // 20

const c = 10;
// c = 20;           // TypeError: Assignment to constant variable

Best practice: use const by default, let when the value must change, and avoid var.

Question 2: What is hoisting?

JavaScript registers declarations before running the code. This is called hoisting.

console.log(a);   // undefined (var is hoisted and set to undefined)
var a = 10;

console.log(b);   // ReferenceError: Cannot access 'b' before initialization
let b = 10;
  • var is hoisted and initialised to undefined, so reading it early gives undefined.
  • let and const are hoisted too, but they sit in the temporal dead zone from the start of the block until the declaration line. Reading them there throws a ReferenceError.

Question 3: Why does the notes' example print 30 (p. 36)?

function printHello() {
  var a = 20;          // function-scoped
  if (true) {
    var a = 30;        // same variable, not a new one
    console.log(a);    // 30
  }
  console.log("F ->", a); // 30
}
printHello();

var ignores block scope. The var a = 30 inside the if block is the same variable as the var a = 20 in the function, so it overwrites it. With let, the inner a would be a separate variable, and the last line would print 20:

function printHello() {
  let a = 20;
  if (true) {
    let a = 30;        // new variable, only inside this block
    console.log(a);    // 30
  }
  console.log("F ->", a); // 20
}

Question 4: Can you change a const object or array?

Yes. const stops you re-assigning the variable, not changing what the object contains.

const user = { name: 'Asha' };
user.name = 'Ravi';        // OK
user.age = 30;             // OK
console.log(user);         // { name: 'Ravi', age: 30 }

// user = { name: 'New' }; // TypeError: Assignment to constant variable

const list = [1, 2];
list.push(3);              // OK
console.log(list);         // [1, 2, 3]

To make an object truly unchangeable, use Object.freeze(user).

Coding task 2: Variables for a test run

const testName = 'Login with valid credentials'; // never changes
const browser = 'chromium';                      // never changes
let retryCount = 0;                              // changes after each retry
let isHeadless = true;                           // const works too if it never changes

retryCount++;
console.log(`${testName} on ${browser}, retries: ${retryCount}, headless: ${isHeadless}`);
// Login with valid credentials on chromium, retries: 1, headless: true

Coding task 3: Swap two variables, three ways

let a = 5, b = 10;

// 1) Temporary variable
let temp = a;
a = b;
b = temp;
console.log(a, b);   // 10 5

// 2) Arithmetic (numbers only)
a = a + b;           // 15
b = a - b;           // 10
a = a - b;           // 5
console.log(a, b);   // 5 10

// 3) Destructuring (modern, works for any type)
[a, b] = [b, a];
console.log(a, b);   // 10 5

Coding task 4: Valid and invalid identifiers

Rules: start with a letter, _ or $; later characters can also be digits; no spaces or hyphens; no reserved keywords.

// Valid
var userName = 'a';
var _id = 1;
var $price = 99;
var name1 = 'b';
var π = 3.14;          // Unicode is allowed, but avoid it in real projects

// Invalid (each causes a SyntaxError)
// var 1name = 'x';    // starts with a digit
// var my-name = 'x';  // hyphen is the minus operator
// var my name = 'x';  // spaces not allowed
// var class = 'x';    // reserved keyword
// var user@id = 'x';  // special character

Identifiers are case-sensitive, so NAME and name1 are different variables, as your notes show.
